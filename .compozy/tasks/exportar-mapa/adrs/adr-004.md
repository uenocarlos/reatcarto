# ADR-004: Fixed REAT/FURG Institutional Branding on Exports

## Status

Accepted

## Date

2026-08-03

## Context

printJs stamps every export with institutional footer text (ReatCarto copyright, cartographic basemap credits, REAT research core, FURG) and the REAT logo. Authorship and technical-responsible lines remain user-filled for the specific map product. Product-direction clarification chose to keep this institutional branding as in printJs rather than fully user-customizable footers.

## Decision

Every successful export (PNG and PDF) includes the **fixed institutional footer branding** equivalent to printJs:

- Product copyright line for ReatCarto
- Basemap credit line for cartographic base sources used by the product
- Nucleo / REAT and FURG attribution text
- Institutional logo asset (REAT)

Authorship and technical-responsible fields remain **editable in the export window** for per-map credit. Footer institutional lines and logo are **not** user-editable in the export UI for this version (code/product asset changes only).

Title default is the map name; authorship fields start empty.

## Alternatives Considered

### Alternative 1: Profile-driven branding only

- **Description**: Footer from user’s organization and name; no REAT lock-in.
- **Pros**: Flexible multi-tenant branding.
- **Cons**: Breaks institutional identity of the product’s origin workspace.
- **Why rejected**: User selected printJs REAT/FURG default branding.

### Alternative 2: Fully editable footer and logo per export

- **Description**: User replaces every line and uploads logo.
- **Pros**: Maximum flexibility.
- **Cons**: Brand dilution, complexity, misuse.
- **Why rejected**: User chose fixed institutional branding.

## Consequences

### Positive

- Consistent institutional identity on delivered maps.
- Clear separation: map credit fields vs institution.

### Negative

- Other institutions using ReatCarto cannot rebrand export footers in this version.

### Risks

- Logo asset missing in React packaging → techspec must guarantee the logo ships with the client bundle or static assets path equivalent to printJs.

## Implementation Notes

Exact copy of institutional footer strings should match printJs intent (Portuguese institutional language). Translation/localization beyond product UI language is out of scope unless already global in the app.
