# ADR-004: Live Preview and Per-Map Persistence of Export Settings

## Status

Accepted

## Date

2026-08-02

## Context

Reference screens show an “Atualizar Preview” action, but field users need immediate feedback. Owners repeatedly export the same map and should not reconfigure title, legend, basemap, and location every time.

## Decision

- The composition preview updates live as options change; a dedicated refresh button is not required (it may be omitted or remain as an optional no-op-free shortcut only if it does not imply stale preview).
- Export configuration persists per map and is restored when the owner reopens the export screen for that map.
- Persisted settings include metadata, legend layout options, layer/tag visibility choices, basemap, location-map options, colors, paper/orientation/DPI, and related composition choices.

## Alternatives Considered

### Alternative 1: On-demand preview only

- **Description**: Options apply only after “Atualizar Preview”.
- **Pros**: Fewer re-renders on heavy maps.
- **Cons**: Easy to export a stale preview; slower iteration.
- **Why rejected**: User chose live preview.

### Alternative 2: Session-only settings

- **Description**: Defaults reset every open.
- **Pros**: Simpler storage.
- **Cons**: Repeats setup for every export.
- **Why rejected**: User chose per-map persistence.

### Alternative 3: Persist only title/author/responsible

- **Description**: Layout options reset each time.
- **Pros**: Less stored state.
- **Cons**: Legend and location setup is the costly part.
- **Why rejected**: User chose full configuration persistence.

## Consequences

### Positive

- Faster iteration and repeatable branded exports.
- Preview fidelity to the PNG is the default expectation.

### Negative

- Live updates may tax devices with many elements or offline tiles.

### Risks

- Stale persisted state after elements are deleted → restore safely and drop visibility flags for missing elements without crashing.

## Implementation Notes

TechSpec defines storage location (local, server map metadata, or both) and conflict behavior after sync. Persistence must not leak export settings across maps or users.
