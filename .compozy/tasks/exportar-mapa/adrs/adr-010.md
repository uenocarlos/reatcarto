# ADR-010: Composition Capture Stack and Cartographic Defaults

## Status

Accepted

## Date

2026-08-02

## Context

`ExportMapModal` already captures a DOM composition with `html2canvas`, but basemap offline paths are inconsistent, satellite providers differ from the editor, the scale bar is a fixed fake, paper size barely affects the frame, PDF remains in the UI, and the default legend position must be fixed for first open.

## Decision

### Capture and delivery

- Keep **DOM composition capture via `html2canvas`** of the preview root for PNG only.
- Remove PDF as an export choice from this feature UI and stop calling `jsPDF` from the composition export path.
- Web: browser download of PNG. Native Capacitor: `Filesystem` (Cache) + `Share.share`.
- Export success toasts only after download starts or share sheet is presented with a generated file.
- Wait for required basemap tiles and boundary geometries (with timeout); otherwise fail visibly — never claim success with a blank/unusable basemap when Offline or online tiles cannot load.

### Basemaps

- Claro = Carto light; OSM = OpenStreetMap; Satellite = **ArcGIS World Imagery** (same as editor); Offline = **`tileManager` / `offline_tiles`** via Capacitor Filesystem converted with `Capacitor.convertFileSrc`.
- Offline option is **enabled only on native Capacitor**; disabled (not selectable / clearly unavailable) on web.

### Layout defaults and chrome

- First-open default **legend position = `inside`** (drag/resize within map frame). Persist overrides thereafter.
- Legend beside/below grow the composition canvas (ADR-005); columns 1–6; font 8–18px; spacing compact/normal/wide.
- Preview frame uses **paper size × orientation aspect ratio**; PNG pixels = that composition × (`dpi / 96`) scale (existing html2canvas pattern).
- **Dynamic scale bar** from map resolution/zoom; north arrow and graticule remain always on.
- Footer uses institutional text plus `public/logo.png` (fallback to text mark if image fails); IBGE line per ADR-009 when location layers used.

### Entry

- Discoverable **Export** control on the owned-map editor (`MapEditor`) that sets `showExport` true; absent on public gallery routes.

## Alternatives Considered

### Alternative 1: leaflet-image / canvas map-only capture

- **Description**: Capture map pane separately from HTML chrome.
- **Pros**: Sometimes sharper tiles.
- **Cons**: Harder to keep legend/footer pixel-perfect with preview.
- **Why rejected**: Preview-equals-PNG favors one DOM tree + html2canvas.

### Alternative 2: Google satellite tiles in export

- **Description**: Keep current modal URL.
- **Pros**: Familiar imagery.
- **Cons**: ToS/CORS risk with html2canvas; diverges from editor.
- **Why rejected**: User asked for free/best; ArcGIS matches editor.

### Alternative 3: Static `/tiles` folder for offline

- **Description**: Web-served tile directory.
- **Pros**: Simple on web.
- **Cons**: Empty today; duplicates Capacitor cache.
- **Why rejected**: User chose `tileManager` / native-only offline.

## Consequences

### Positive

- One faithful preview→PNG path; aligned basemaps; honest scale; paper-aware layout.
- Offline story matches how tiles are already downloaded on device.

### Negative

- Web users cannot use Offline basemap in this PRD.
- html2canvas remains sensitive to tainted canvas / CORS — useCORS and ArcGIS/Carto/OSM must be verified.

### Risks

- High DPI + large paper + satellite may OOM — catch errors and toast failure.
- Leaflet not fully painted before capture — gate on `tileload` / loading flags before export.

## Implementation Notes

Extend `src/components/map/ExportMapModal.jsx` and extract helpers under `src/components/map/export/` and `src/lib/export/` as needed. Wire Export button in `MapEditor.jsx`. Reuse `getLocalTileUrl` from `tileManager.js` for a custom Leaflet tile layer in the preview when `baseLayer === 'offline'`.
