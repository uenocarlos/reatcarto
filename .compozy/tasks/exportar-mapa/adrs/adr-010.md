# ADR-010: Debounced Live Preview with Optional Explicit Refresh

## Status

Accepted

## Date

2026-08-03

## Context

US-003 requires WYSIWYG preview that tracks legend position, paper-affecting layout, insets, and credit text. Fully live keystroke updates can thrash Leaflet `invalidateSize` and tile redraws; fully manual refresh frustrates users who expect the layout they just configured.

## Decision

1. **Layout/text/legend formatting** update the preview DOM **live with debounce** (target 300–500 ms) from the export session state.
2. Provide an explicit **“Atualizar prévia”** control that immediately flushes debounce and re-triggers map tile/overlays readiness (and inset redraws).
3. Generation (export) always uses **current session state and the composition DOM at export time**, after an optional pre-capture settle (wait-for-tiles), regardless of whether the user manually clicked refresh last.

## Alternatives Considered

### Alternative 1: Explicit refresh only

- **Description**: No automatic preview until button.
- **Pros**: Zero thrash.
- **Cons**: Stale preview is easy to export by mistake.
- **Why rejected**: User preferred live debounced updates.

### Alternative 2: Fully live every keystroke

- **Description**: Immediate re-render without debounce.
- **Pros**: Maximum snappiness for text.
- **Cons**: Performance risk with maps and large legends.
- **Why rejected**: Debounce balances UX and load.

## Consequences

### Positive

- Preview converges to last settings under rapid option changes (US-003.EC-2).
- Power users force a map settle when tiles lagged.

### Negative

- Brief preview lag after typing equals debounce window.

### Risks

- Debounce mid-flight overlapping export click → export path must read latest state and re-settle maps, not rely solely on last preview paint.

## Implementation Notes

Hook: `useExportPreviewSync` owned by export shell. Debounce only client-side; no server.
