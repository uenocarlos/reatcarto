# ADR-008: Client-Side Capture with html-to-image and jsPDF

## Status

Accepted

## Date

2026-08-03

## Context

PRD and ADR-001 require browser-local PNG/PDF generation with paper, DPI, and composition fidelity. Legacy `printJs.php` uses `html2canvas` + `jspdf`. The React app already depends on `html2canvas` and `jspdf`, but neither is imported from `src/` yet. Design clarification preferred a modern capture library over continuing with html2canvas.

## Decision

Generate exports **entirely in the browser** with this pipeline:

1. Wait for main (and inset) map tiles and vector layers to settle (load hooks + short settle delay; abortable).
2. Optionally freeze interactive Leaflet containers into static images for the capture pass (legacy technique: replace map pane with captured map image to avoid WebGL/tile quirks).
3. Rasterize the full preview composition root with **`html-to-image`** (`toPng` / `toCanvas`) at `pixelRatio` derived from `dpi / 96`.
4. **PNG**: download via blob URL + temporary `<a download>`.
5. **PDF**: wrap raster with **`jspdf`** using selected paper size and orientation; `addImage` then `save`.
6. **Single-flight** generation per open export session; export control disabled while in-flight; close aborts where possible.

Add npm dependency `html-to-image`. Prefer it as the capture API surface; remove or leave unused `html2canvas` only if no remaining callers.

No PHP print endpoint and no server-side PDF farm for this version.

## Alternatives Considered

### Alternative 1: Keep html2canvas + jspdf

- **Description**: Port printJs literally.
- **Pros**: Proven in legacy; already installed.
- **Cons**: html2canvas maintenance and CORS/quirks track record; user chose html-to-image family.
- **Why rejected**: Explicit design choice during tech clarification.

### Alternative 2: leaflet-image / pure canvas compose of map only

- **Description**: Capture map canvas alone; build legend and chrome outside HTML capture.
- **Pros**: Finer control of map pixels.
- **Cons**: Reimplements layout rasterization; harder parity with HTML legend/footer.
- **Why rejected**: Full composition capture matches printJs flow and legend-heavy HTML.

### Alternative 3: Server-side rendering

- **Description**: Queue tile fetch and PDF on the backend.
- **Pros**: Device memory offload.
- **Cons**: Contradicts ADR-001 efficiency class; new infra and auth surface.
- **Why rejected**: Product non-goal and prior ADRs.

## Consequences

### Positive

- Immediate personal downloads; no queue.
- Matches paper/DPI composition intent from a single DOM tree.

### Negative

- Device memory bound (especially A3 @ 600 DPI on phones).
- Tile CORS must succeed; use CORS-friendly tile URLs already in product basemaps.

### Risks

- Incomplete tiles if capture races load → wait-for-tiles + user-visible failure/retry.
- Library swap from html2canvas may need a short prototyping pass for Leaflet markers/shadow panes; keep freeze-map-to-image fallback from printJs.

## Implementation Notes

Generation module: `src/lib/export/generateExport.js` (pure functions + abort signal). UI calls it from the export shell. Filename: sanitized title + `.png` / `.pdf`. Download delivery remains browser anchor also in Capacitor WebView (no Filesystem/Share path in v1).
