# ADR-008: Independent Export Visibility Overlay

## Status

Accepted

## Date

2026-08-02

## Context

Owners need to hide categories and elements for the PNG without deleting field data (ADR-006). The live editor already shows all owned elements. Coupling export toggles to editor visibility would mutate the editing session and risk surprising restore behavior when the modal closes.

## Decision

- Export category and element visibility live only in `export_settings` and apply only inside the export preview/PNG pipeline.
- Closing or canceling the export modal leaves the editor map visibility unchanged.
- Category-off hides all child elements in the export composition until the category is on again.
- Global name tags apply only to elements visible in the export composition.
- Defaults: all existing categories/elements visible for export; tags off.

## Alternatives Considered

### Alternative 1: Mirror into editor while modal open

- **Description**: Temporarily hide layers on the live map.
- **Pros**: One renderer path.
- **Cons**: Side effects on editing; restore bugs on crash/close.
- **Why rejected**: User chose independence.

## Consequences

### Positive

- Safe composition experiments without touching field geometries.
- Clear mental model: export settings vs map document.

### Negative

- Preview must re-filter elements itself (duplicate of editor filter logic scoped to export).

### Risks

- Drift between editor styling and export rendering — mitigate by sharing style/icon helpers already used by `ExportMapModal` / `LeafletMap`.

## Implementation Notes

Store `hiddenCategoryIds: string[]` and `hiddenElementIds: string[]` (or equivalent sparse maps). Effective visibility = category on AND element on. Prune ids missing from current element list on load.
