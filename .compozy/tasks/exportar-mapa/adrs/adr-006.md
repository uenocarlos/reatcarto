# ADR-006: Inherit Editor Map State into Export Session

## Status

Accepted

## Date

2026-08-03

## Context

Efficiency of the legacy flow depends on continuity: users arrange the map, then print what they see. Resetting basemap, layer visibility, and extent when opening export forces redundant work and diverges from printJs’s practical use.

## Decision

When the owner opens export from the editor:

1. **Viewport** (center and zoom — and view extent) matches the editor map at open time.
2. **Layer / element visibility** matches the editor’s current hide/show state as the starting export layer control state.
3. **Basemap** matches the editor’s current basemap when possible (mapped to the three export basemap options).
4. Within the export session, the owner may change layers, basemap, labels, layout, and location options for the **export surface** without requiring those changes to permanently rewrite the editor after **cancel**. Successful export does not oblige altering the editor; product prefers no surprise permanent editor mutations from cancel.

Legend content is derived from the map elements included as visible for export (symbols and names consistent with how the product groups styles for layers).

## Alternatives Considered

### Alternative 1: Fixed printJs defaults on every open

- **Description**: Always Carto, all layers, default extent from map record only.
- **Pros**: Predictable form.
- **Cons**: Ignores in-progress editing; slower workflow.
- **Why rejected**: User chose inherit-from-editor.

### Alternative 2: Inherit viewport only

- **Description**: Zoom/center from editor; layers and basemap reset.
- **Pros**: Simpler state.
- **Cons**: Loses half the continuity benefit.
- **Why rejected**: User chose full inheritance of viewport, layers, and basemap.

## Consequences

### Positive

- Short path from “map looks right” to “file downloads.”
- Layer toggles in export start aligned with the user’s mental model.

### Negative

- Hidden elements stay off export until re-enabled in the export panel.

### Risks

- Editor and export basemap option sets diverge slightly → define a clear mapping for each product basemap option.

## Implementation Notes

Technical mechanism for clone map vs shared map instance is TechSpec. Product rule is what the user sees when the export UI first paints and after cancel.
