# ADR-006: Layer Visibility, Tags, and Export Gates

## Status

Accepted

## Date

2026-08-02

## Context

Owners need to compose a clean export without deleting field data: hide categories or individual elements, optionally show element name tags, and prevent incomplete branded outputs.

## Decision

### Layer control

- Owners can toggle visibility by **category** and by **individual element**.
- Hiding an item removes it from both the map preview and the legend.
- Location-derived legend entries (state / municipality) follow their own checkboxes and colors independently of drawn elements.

### Tags

- A single global switch shows or hides names for all currently visible elements on the map.
- Elements without a usable name simply show no label when tags are on.

### Metadata

- **Title** and **Author** are required before export.
- **Technical responsible** is optional; when filled, it appears with the footer block.

### Export gates

Export is blocked (with clear UI feedback) when any of the following hold:

1. Title or Author is blank.
2. Location insets are set to 1 or 2 and state or municipality is missing.
3. There is no visible content contribution: at least one drawn element must be visible on the map **or** at least one legend item must be present (including location legend entries when enabled).

### Always-on chrome

Coordinate graticule, scale bar, and north arrow are always present on the exported composition in this PRD (no toggles).

### Basemaps

Basemap choices are: Carto light (“Claro”), OpenStreetMap, Satellite, and Offline (tiles folder).

### Footer

The composition footer always includes the institutional RealCarto / (R)EAT / FURG information block and logo treatment consistent with the product branding references, plus author and technical responsible lines when provided.

## Alternatives Considered

### Alternative 1: Category-only layer toggles

- **Description**: No per-element switches.
- **Pros**: Simpler UI.
- **Cons**: Cannot omit a single noisy feature.
- **Why rejected**: User required both levels.

### Alternative 2: Allow export with empty map content

- **Description**: Basemap-only PNG is allowed.
- **Pros**: Faster “empty frame” tests.
- **Cons**: Produces non-informative field/report deliverables.
- **Why rejected**: User requires at least one visible map or legend item.

### Alternative 3: All metadata optional

- **Description**: Export without title/author.
- **Pros**: Fastest field path.
- **Cons**: Weak attribution for reports.
- **Why rejected**: User required title and author.

## Consequences

### Positive

- Fine-grained composition control without mutating the source map permanently in the editor session beyond export settings.
- Prevents incomplete locator or unattributed exports.

### Negative

- Owners must satisfy gates before download/share.

### Risks

- Category off + some elements thought visible → clarify that category toggle overrides children when off.

## Implementation Notes

Visibility and tag choices belong to export configuration (persisted per map) and must not silently delete elements from the map document. TechSpec clarifies whether editor map visibility is independent of export visibility.
