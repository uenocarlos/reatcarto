# ADR-011: Non-Empty Title Required for Download

## Status

Accepted

## Date

2026-08-03

## Context

PRD business rules listed empty title as optionally allowed; stories US-004.EC-1 required a single product rule. Institutional deliverables need a titled map product; default prefill from `map.name` covers normal open.

## Decision

**Block export/download when the title field is empty or whitespace-only** after trim. Show inline validation (and disable or guard the Export action) with a clear Portuguese message. Opening with blank `map.name` pre-fills empty title; the owner must type a title before a successful download. Preview may still render with an empty title region while composing.

Successful download filename is derived from the non-empty title (sanitized) plus extension.

## Alternatives Considered

### Alternative 1: Allow empty title

- **Description**: Empty title region; download anyway.
- **Pros**: Zero friction.
- **Cons**: Untitled institutional files; weaker printJs delivery quality.
- **Why rejected**: User chose block during tech clarification.

### Alternative 2: Silent fallback name

- **Description**: Substitute map.name or “Mapa sem título” if empty.
- **Pros**: Always downloadable.
- **Cons**: Hidden renaming; product asks for explicit title.
- **Why rejected**: User chose hard block.

## Consequences

### Positive

- Every downloaded product has an intentional title and filename base.
- Validation is local to client; no server model change.

### Negative

- Owner with intentionally untitled draft must invent a temporary title to export.

### Risks

- None material.

## Implementation Notes

Validation function `assertExportTitle(title): void | ExportValidationError` used by generate path and UI.
