# ADR-009: IBGE Online Boundaries with Static Fallback

## Status

Accepted

## Date

2026-08-02

## Context

Brazil locator insets and municipal mesh require official administrative boundaries (ADR-002). The repo has no boundary assets today. Field users need a working path offline; online users should get the freshest IBGE malha.

## Decision

- **When online**: fetch the latest available **IBGE Malhas Digitais** geometries and **Localidades** codes/names at runtime for state and municipality selection and inset/mesh rendering.
- **When offline or IBGE fails**: use a simplified static bundle under `public/geo/` (UFs + municipalities) as the sole fallback; document the bundle’s reference malha version in code comments / README next to the assets.
- Do not require a successful IBGE refresh to export when the fallback catalog can satisfy the selected UF/municipality.
- If insets are requested and neither IBGE nor fallback can supply the selected geometry, block export with a clear error (no empty inset claimed as success).
- When insets, main-map location outline, mesh, or location legend entries are present in the composition, append an **IBGE credit line** to the institutional footer; omit that line when location features are unused (insets None and no location overlays).

## Alternatives Considered

### Alternative 1: Bundle-only canonical

- **Description**: Always read `public/geo/`.
- **Pros**: Deterministic offline.
- **Cons**: Stale malha until manual asset updates.
- **Why rejected**: User preferred IBGE when online.

### Alternative 2: PostGIS boundary tables

- **Description**: Server hosts polygons.
- **Pros**: Authz and simplification server-side.
- **Cons**: Large migration and hosting cost for this PRD.
- **Why rejected**: Deferred; client fetch + static fallback is enough.

### Alternative 3: Cache IBGE responses in IndexedDB as offline source

- **Description**: Prefer last IBGE download when offline.
- **Pros**: Fresher offline data.
- **Cons**: Storage size; partial cache complexity.
- **Why rejected**: User rule is `public/geo/` when offline/API fails.

## Consequences

### Positive

- Fresh boundaries online; field composition still works offline via fallback.
- Explicit IBGE attribution when those layers appear.

### Negative

- Online/offline compositions for the same UF may differ slightly in geometry detail.
- Static bundle must be kept usable for all Brazilian municipalities in the product catalog.

### Risks

- IBGE API downtime or CORS — mitigate with timeout, user-visible error, and automatic fallback to `public/geo/`.
- Large municipality GeoJSON — simplify for inset zoom levels; lazy-load by UF where possible.

## Implementation Notes

Client module `src/lib/export/brazilBoundaries.js`: `listStates`, `listMunicipalities(stateCode)`, `getStateGeometry`, `getMunicipalityGeometry`, `getMunicipalMesh(stateCode)` with `{ source: 'ibge' | 'fallback' }`. Prefer UF-scoped mesh files in the fallback bundle. Inset count 2 uses a South America/Brazil context layer from the same module (static coastline/Brazil outline acceptable in fallback).
