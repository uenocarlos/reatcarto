# ADR-002: Brazil-First Location Maps with Official Administrative Boundaries

## Status

Accepted

## Date

2026-08-02

## Context

Users need locator insets (mapas de localização) showing state and municipality context, matching cartographic practice for Brazilian academic and extension maps. The product has no administrative-boundary model today. Worldwide coverage would expand data and UX scope without a current requirement.

## Decision

Support location maps for Brazil only in this PRD: the user selects a Brazilian state and municipality. Inset counts are None, 1, or 2:

- **1 map**: state extent with the selected municipality highlighted.
- **2 maps**: South America context highlighting Brazil/state, plus the state extent with the municipality highlighted.

The selection also drives the main map: municipality outline, optional municipal mesh, optional legend entries for state and municipality, and per-entity colors. Expansion beyond Brazil is an explicit Non-Goal for this PRD, while the UX may remain structured so a later country catalog can plug in.

When 1 or 2 insets are selected, export is blocked until both state and municipality are chosen, with clear feedback in the preview/options UI.

## Alternatives Considered

### Alternative 1: Brazil only with no future-facing structure

- **Description**: Hard-code Brazil with no acknowledgment of later expansion.
- **Pros**: Slightly simpler messaging.
- **Cons**: Future international work would feel bolted on.
- **Why rejected**: User asked for Brazil now with room for other countries later, documented as out of scope.

### Alternative 2: Worldwide localities in this delivery

- **Description**: User picks locations anywhere on Earth.
- **Pros**: Broader market reach.
- **Cons**: No boundary source strategy; large data and QA burden.
- **Why rejected**: User deferred non-Brazil coverage.

### Alternative 3: Always require at least one inset

- **Description**: Only 1 or 2 insets, never none.
- **Pros**: Stronger cartographic completeness.
- **Cons**: Slows field exports that do not need insets.
- **Why rejected**: User selected None, 1, or 2.

## Consequences

### Positive

- Matches reference UI and Brazilian academic locator practice.
- Clear validation prevents empty insets in the PNG.

### Negative

- Non-Brazilian maps cannot use official locator insets in this version.

### Risks

- Boundary data freshness (e.g., IBGE mesh updates) may lag; TechSpec must name the source and update approach.

## Implementation Notes

TechSpec owns boundary data acquisition, simplification for preview performance, and attribution if required beyond the existing footer basemap credits.
