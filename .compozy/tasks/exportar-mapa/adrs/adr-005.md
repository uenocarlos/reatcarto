# ADR-005: Full Mobile Parity for Export Composition UX

## Status

Accepted

## Date

2026-08-03

## Context

printJs’s layout is control panel plus large live preview, historically desktop-first. ReatCarto is used on field devices; the user required export UX parity on phone, not a blocked or “desktop only” export.

## Decision

The export composition experience is a **first-class mobile flow**: controls and preview remain usable on phone and tablet, with stacked layout and scrollable configuration where side-by-side is impossible. High DPI still generates large files; the product may show progress and duration feedback but must not hide export solely because the viewport is narrow.

Desktop retains the recommended two-pane / rich-preview comfort layout.

## Alternatives Considered

### Alternative 1: Desktop-only export button

- **Description**: Hide export under a width breakpoint.
- **Pros**: Avoids unusable cramped UI and failed high-DPI memory cases on weak phones.
- **Cons**: Blocks field owners who finalize maps on phones.
- **Why rejected**: User chose full mobile UX parity.

### Alternative 2: Desktop-first with degraded but available UI

- **Description**: Allow mobile with limited preview quality.
- **Pros**: Compromise on quality.
- **Cons**: Half measures can hide bugs and skip real mobile design.
- **Why rejected**: User required complete mobile usability parity.

## Consequences

### Positive

- Owners can compose and download on the same device they edit.
- Stories and tests cover narrow viewports.

### Negative

- More layout work for responsive controls and preview.
- Weak devices may struggle at 300–600 DPI; failures must fail cleanly.

### Risks

- Memory exhaustion at high DPI on mobile → message user with ability to lower DPI and retry.

## Implementation Notes

Responsive design details live in TechSpec; product requires that every export control available on desktop remains reachable on mobile (no permanent feature cut on phone).
