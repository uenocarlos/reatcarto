# ADR-005: Legend Placement and Growing Composition Canvas

## Status

Accepted

## Date

2026-08-02

## Context

Users need flexible legend placement: inside the map frame, beside it, or below it. Inside placement must support free positioning and resizing within the map area. External placement must not cover map content.

## Decision

- Offer three legend positions: **inside**, **beside** (side of the map), and **below**.
- **Inside**: the legend is an interactive frame within the map area; the owner can drag it anywhere inside that area and resize it. It remains constrained to the map frame.
- **Beside** or **below**: the legend sits outside the map frame; the overall composition grows so the PNG includes map, legend, title (when present), and footer without covering the map.
- Legend appearance controls: columns **1–6**, font size **8px–18px**, item spacing **compact / normal / wide**.

## Alternatives Considered

### Alternative 1: Fixed-size page that shrinks the map

- **Description**: Keep outer dimensions fixed; map shrinks to make room for an external legend.
- **Pros**: Predictable pixel dimensions.
- **Cons**: Changes map scale unexpectedly relative to the editor view.
- **Why rejected**: User chose a growing total area.

### Alternative 2: Inside-only legend

- **Description**: No beside/below modes.
- **Pros**: Simpler layout engine.
- **Cons**: Dense legends obscure geography.
- **Why rejected**: User required all three positions.

## Consequences

### Positive

- Matches QGIS/ArcGIS-style layout expectations and the provided reference images.
- External legends stay readable without hiding features.

### Negative

- PNG pixel dimensions vary with legend position and content length.

### Risks

- Very long legends at large fonts may produce tall/wide images; columns and spacing mitigate crowding.

## Implementation Notes

When all legend items are hidden by layer controls, treat the legend as empty for validation purposes (see ADR-006). Drag/resize applies only to the inside position.
