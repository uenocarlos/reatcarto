# ADR-003: Full Drawing Editor on Desktop Only

## Status

Accepted

## Date

2026-08-12

## Context

The MVP drawing surface is object-based (pencil, shapes, select, move, resize, rotate). Precise transforms and multi-select (P1) are poor fits for first-pass touch UX. The product still needs field users on mobile to **use** custom icons already in their library.

## Decision

- **Desktop**: full drawing editor (per priority tiers in the PRD).
- **Mobile / touch-primary**: users may select built-in icons and library icons; they **cannot** open the drawing creator. UI explains that creating icons requires desktop.
- Library apply/remove/name and color-preserving display work on both platforms wherever StylePanel is available.

## Alternatives Considered

### Alternative 1: Full editor on mobile

- **Description**: Same toolset on phone/tablet.
- **Pros**: Create icons in the field.
- **Cons**: High UX risk for transforms; inflates MVP.
- **Why rejected**: User confirmed desktop-complete / mobile library-only.

### Alternative 2: Mobile subset (pencil + color only)

- **Description**: Simplified freehand on mobile.
- **Pros**: Some field creation.
- **Cons**: Two editor products; quality and support cost; still weak for “object editor” promise.
- **Why rejected**: Prefer one complete desktop editor for MVP.

## Consequences

### Positive

- Focused MVP quality on pointer devices.
- Mobile retains reuse value via the library.

### Negative

- Field workers cannot invent new symbols without a desktop session.

### Risks

- Users discover “Desenhar” disabled on mobile as a dead-end — mitigate with clear copy and prominent library section.

## Implementation Notes

Breakpoint / capability detection is TechSpec. Product requirement is behavioral: drawing entry is unavailable on mobile MVP.
