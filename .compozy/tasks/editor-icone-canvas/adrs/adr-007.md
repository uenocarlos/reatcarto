# ADR-007: Color Bitmap When custom_icon_url Is Set

## Status

Accepted

## Date

2026-08-12

## Context

`createColoredIcon` currently treats any URL/`*.svg` path as a CSS mask tinted by `icon_color`. Drawn library icons must keep original colors on map, legend, and export (ADR-001). Built-in `/icons/*.svg` values live in `icon_name` and must remain tintable.

## Decision

- If `customUrl` (argument from `style.custom_icon_url`) is a non-empty string → render a **color-preserving bitmap** inside `L.divIcon` (centered `<img>` with `object-fit: contain`, transparent background; no mask; ignore `color` for the artwork).
- If only `iconName` is a path/`http`/`*.svg` (legacy built-in SVG paths) → keep **mask + `icon_color`**.
- Named Lucide keys → keep `getIconSvg` tint path.
- `ExportLegend` symbol for points with `custom_icon_url` uses the same `<img>`/bitmap approach (CSS class without mask).
- Selecting a built-in icon in StylePanel sets `custom_icon_url: ''` (and the chosen `icon_name`) so tinting returns.

## Alternatives Considered

### Alternative 1: Explicit `style.icon_display` flag

- **Pros**: Explicit mode.
- **Cons**: Extra field to keep in sync; unnecessary if library always uses `custom_icon_url`.
- **Why rejected**: User chose URL presence as the switch.

### Alternative 2: Only `/php/icons/` URLs are color

- **Pros**: Legacy custom URLs could stay masked.
- **Cons**: ADR-001/PRD prefer all custom URL customs color-preserving; special-casing is fragile.
- **Why rejected**: User chose option A (any `custom_icon_url`).

## Consequences

### Positive

- One clear rule for implementers and tests.
- StylePanel `<img>` preview matches map/legend/export.

### Negative

- Any future monochrome custom URL intended for tinting via `custom_icon_url` would not tint — acceptable; use `icon_name` paths for tintable SVGs.

### Risks

- Broken image URLs → need onerror fallback in marker HTML (neutral placeholder) so Leaflet does not throw.

## Implementation Notes

Update `pointIcon.js`, `ExportLegend.jsx`, and legend CSS. Keep anchor behavior: custom bitmaps use center anchor (half, half) unless product later distinguishes pin-like customs; default **center** for drawn icons.
