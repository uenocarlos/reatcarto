# ADR-001: Preserve Original Colors for Drawn Icons

## Status

Accepted

## Date

2026-08-12

## Context

The Map Editor already supports `custom_icon_url` on point `style`, but map, legend, and export render custom URLs as CSS masks recolored by `icon_color`. A canvas icon editor with a color palette only delivers user value if those colors survive on the map. The StylePanel preview already shows custom icons as `<img>` (full color), which would diverge further from the map if mask rendering stayed the default for drawn icons.

## Decision

Drawn (and library) custom icons display with their original colors on the interactive map, legend, and export. They are not recolored by `icon_color`. Built-in / path-based icons that rely on mask or SVG tinting keep using `icon_color` as today.

## Alternatives Considered

### Alternative 1: Silhouette / mask recolorable via `icon_color`

- **Description**: Keep the current mask pipeline for all custom URLs.
- **Pros**: Minimal change to `pointIcon` / legend / export; consistent tinting with built-ins.
- **Cons**: Color tools in the editor become misleading; product value of a drawing editor collapses.
- **Why rejected**: Conflicts with the stated product preference and user confirmation to preserve colors.

### Alternative 2: Hybrid — color on map, silhouette in legend

- **Description**: Full-color markers on the map; legend uses mask or a generic “Custom” glyph.
- **Pros**: Slightly less legend complexity.
- **Cons**: Map and legend disagree; cartographic exports look wrong.
- **Why rejected**: Users need the same symbol identity in map, legend, and export.

## Consequences

### Positive

- Drawing with color is meaningful end-to-end.
- StylePanel preview, map, legend, and export can share one visual contract for library icons.

### Negative

- Existing mask-only treatment of `custom_icon_url` must be specialized (or replaced) for colored library icons.
- `icon_color` no longer affects drawn icons; users must redraw if they want a different palette.

### Risks

- Mixed points (built-in tinted vs colored custom) may confuse users expecting one color control — mitigate with clear UI copy when a library icon is applied (`icon_color` does not tint it).

## Implementation Notes

Product requires color fidelity everywhere the point icon appears. How rendering switches (e.g. `<img>` vs mask detection) belongs to the TechSpec.
