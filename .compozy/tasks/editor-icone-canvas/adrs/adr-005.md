# ADR-005: Fabric.js for the Icon Canvas Editor

## Status

Accepted

## Date

2026-08-12

## Context

The PRD requires an object-based drawing editor (freehand, shapes, select/move/resize/rotate, later multi-select and undo) that exports a transparent PNG. The React app has no canvas object library today. Choosing the library locks the IconCanvasEditor implementation approach.

## Decision

Use **Fabric.js** (current stable v6.x) as the sole canvas engine inside `IconCanvasEditor`. Export via Fabric `toDataURL` / blob helpers at 256×256 with transparency. P1 undo/redo uses Fabric JSON snapshots on gesture completion (mouse-up), not per-frame.

## Alternatives Considered

### Alternative 1: Konva + react-konva

- **Description**: Declarative React canvas graph.
- **Pros**: Fits React mental model; good transforms.
- **Cons**: Freehand brush + history need more custom glue for this MVP shape.
- **Why rejected**: User chose Fabric for faster object-editor coverage.

### Alternative 2: Raw Canvas 2D / SVG

- **Description**: Hand-rolled hit testing and transforms.
- **Pros**: Zero dependency.
- **Cons**: High risk for selection/rotate/export quality.
- **Why rejected**: Out of proportion to MVP.

## Consequences

### Positive

- Selection, brushes, shapes, and PNG export are library-supported.
- Editor can live as an imperative island inside StylePanel without rewriting map state.

### Negative

- New npm dependency and Fabric-specific test doubles.
- Bundle size increase for Map Editor routes that load the editor (lazy-load the modal).

### Risks

- Fabric v6 API churn — pin a minor version and wrap export helpers in `iconExport.js`.

## Implementation Notes

Lazy-load `IconCanvasEditor` (and `fabric`) only when the user opens “Desenhar ícone” on desktop. Do not load Fabric on mobile StylePanel.
