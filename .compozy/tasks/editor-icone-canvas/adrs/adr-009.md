# ADR-009: Desktop Capability Gate and Online-Only Library

## Status

Accepted

## Date

2026-08-12

## Context

ADR-003 restricts the drawing editor to desktop. US-002 left detection to TechSpec. Offline icon queues were deferred; PRD required no false success offline.

## Decision

1. **Desktop gate:** `canUseIconCanvasEditor()` is true iff `window.matchMedia('(pointer: fine)').matches` and `window.innerWidth >= 768`. StylePanel shows “Desenhar ícone” only when true; otherwise show short copy that creation requires desktop. Library section remains on all platforms.
2. **Online-only library:** Before create/list/remove, client checks connectivity (existing connectivity helper). If offline, show explicit error and do not mutate local optimistic library state. Point `style` apply of an **already known** `custom_icon_url` still follows normal element save (including offline element sync if applicable).
3. **P0 delete object:** IconCanvasEditor supports Delete/Backspace and a toolbar delete control for the selected object.

## Alternatives Considered

### Alternative 1: Width-only or UA/Capacitor platform

- **Pros**: Simpler.
- **Cons**: False positives on large phones; UA fragile.
- **Why rejected**: User chose pointer + width.

### Alternative 2: Offline icon_blobs outbox in MVP

- **Pros**: Field creation offline.
- **Cons**: New sync surface; deferred by product.
- **Why rejected**: User chose online-only library MVP.

## Consequences

### Positive

- Predictable editor availability.
- No half-synced icon catalog offline.

### Negative

- Touch laptops that report coarse pointer may lose the editor — rare; users can attach a mouse.
- Cannot invent new icons offline.

### Risks

- Capacitor WebView width/pointer quirks — verify on target devices; adjust helper only if evidence requires (keep ADR intent).

## Implementation Notes

Place helper at `src/lib/icons/desktopCapability.js`. Unit-test with mocked `matchMedia` and width.
