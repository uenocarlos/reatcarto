# ADR-003: Attribute Mapping — Automatic Pre-Mapping with User Review

## Status

Accepted

## Date

2026-08-10

## Context

Imported GeoJSON and Shapefile features carry arbitrary attribute fields (DBF columns or GeoJSON `properties`). ReatCarto elements store structured fields: name, description, category, style, plus fixed metadata (author, timestamps). A mapping step is needed to translate external attributes into the product model.

## Decision

Before confirming an import, the user sees a **mapping review screen** that:

1. Automatically pre-maps source fields to ReatCarto fields when names match known aliases (e.g., `name`, `nome`, `Name`, `NM` → name; `description`, `descricao`, `desc` → description; `category`, `categoria`, `tipo` → category; style-related fields → style properties).
2. Shows all detected source fields with editable target assignments.
3. Allows the user to mark fields as "ignore" (not imported).
4. Applies the confirmed mapping to all features in the import batch.

Unmapped required fields default to sensible fallbacks: name defaults to a generated label (e.g., feature index or geometry type), description and category may be empty.

## Alternatives Considered

### Alternative 1: Fully automatic, no review

- **Description**: Silent mapping by known field names; unmapped fields discarded.
- **Pros**: Fastest import flow.
- **Cons**: Wrong mappings are hard to detect; regional naming conventions vary.
- **Why rejected**: User wants review step.

### Alternative 2: Fully manual mapping

- **Description**: User maps every field from scratch each time.
- **Pros**: Maximum control.
- **Cons**: Tedious for standard files with obvious field names.
- **Why rejected**: User wants automatic pre-mapping with ability to adjust.

## Consequences

### Positive

- Reduces friction for well-named files while preserving control for non-standard schemas.
- Makes import behavior transparent before commit.

### Negative

- Extra screen in the import flow; may feel heavy for single-feature files.

### Risks

- Shapefile DBF field names are limited to 10 characters, increasing ambiguity; mitigated by showing sample values per column in the review screen.

## Implementation Notes

- Style mapping exports inverse fields on export (ADR-006).
- Shapefile attribute values are limited to 254 characters; truncation must be reported if source values exceed limits.
