# ADR-005: Import Validation — Partial Import with User Confirmation

## Status

Accepted

## Date

2026-08-10

## Context

Real-world GIS files often contain a mix of valid and invalid features: corrupt geometries, unsupported types that cannot be normalized, features exceeding vertex limits, or rows that would push the map over the 5,000-element cap. The product must handle these without silent data loss or opaque failures.

## Decision

After parsing and normalizing a file, the import flow shows a **validation summary** before writing:

- Total features found in file.
- Count of valid features ready to import.
- Count and categorized reasons for invalid/skipped features (geometry type, vertex limit, validation failure, capacity exceeded).
- Optional map preview of valid features overlaid on the current map extent.

The user must explicitly confirm to proceed. Only valid features are imported. If zero valid features remain, import is blocked with an error message. If merge mode would exceed the 5,000-element limit, excess features are listed as skipped due to capacity, and the summary shows how many will actually be imported.

## Alternatives Considered

### Alternative 1: All-or-nothing

- **Description**: Any invalid feature cancels the entire import.
- **Pros**: Predictable complete dataset.
- **Cons**: Rejects entire files for a single bad row; common in legacy Shapefiles.
- **Why rejected**: User chose partial with confirmation.

### Alternative 2: Silent partial import

- **Description**: Import valid features automatically; show errors afterward.
- **Pros**: Fastest path.
- **Cons**: User may not notice missing features.
- **Why rejected**: User wants confirmation before commit.

## Consequences

### Positive

- Transparent handling of imperfect source data.
- User makes an informed decision before modifying the map.

### Negative

- Requires building a preview and summary UI.
- Partial imports may surprise users who expected all features.

### Risks

- Users confirm without reading summary; mitigated by prominent valid/invalid counts and preview map.

## Implementation Notes

- Capacity check: in merge mode, `min(valid_count, 5000 - current_count)` features importable.
- In replace mode, capacity check: `min(valid_count, 5000)`.

## References

- `ELEMENTS_PER_MAP = 5000`, `MAX_VERTICES = 10000` in `php/lib/Limits.php`
