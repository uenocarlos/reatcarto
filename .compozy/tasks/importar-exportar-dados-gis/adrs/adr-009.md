# ADR-009: Server-Side Shapefile Export Generation

## Status

Accepted

## Date

2026-08-10

## Context

Shapefile export requires connectivity (ADR-006) and produces `.shp`, `.shx`, `.dbf`, and `.prj` files packaged in a zip. Client-side generation would add heavy dependencies to the mobile bundle and duplicate geometry validation already available server-side via PostGIS.

## Decision

Generate Shapefile exports on the PHP server via `POST /php/elements/export-shp.php`. The server reads validated geometries from `map_elements`, writes temporary GeoJSON per geometry type, converts to Shapefile using `ogr2ogr` (GDAL), packages layers into a zip, and streams the response. The client triggers download via `triggerDownload()` (same pattern as cartographic PNG/PDF export).

GeoJSON export remains fully client-side (works offline from IndexedDB).

## Alternatives Considered

### Alternative 1: Client-side Shapefile generation (shp-write / shpjs)

- **Description**: Build zip in the browser when online.
- **Pros**: No server dependency.
- **Cons**: Large bundle; DBF encoding edge cases on mobile; duplicates server validation.
- **Why rejected**: User chose server-only generation.

### Alternative 2: Server with client fallback

- **Description**: Try server first; fall back to client if server fails.
- **Pros**: Resilience.
- **Cons**: Two code paths to maintain; inconsistent output.
- **Why rejected**: User chose server-only.

## Consequences

### Positive

- Consistent Shapefile output validated against PostGIS source data.
- No additional client bundle weight for Shapefile writing.
- DBF encoding controlled server-side (UTF-8 with Latin-1 fallback on read; UTF-8 write on export).

### Negative

- Requires GDAL/`ogr2ogr` on the deployment host.
- Shapefile export unavailable when server is unreachable (by design per ADR-006).

### Risks

- Missing GDAL on some dev machines; mitigated by documenting dependency and providing a dev setup check script.

## Implementation Notes

- Mixed geometry types: separate shapefiles per type inside the zip (ADR-012).
- Filename pattern: `{slugified-map-name}-{YYYY-MM-DD}.zip`.
- Request body: `{ map_id, scope: "whole" | "selection", element_ids?: string[] }`.
