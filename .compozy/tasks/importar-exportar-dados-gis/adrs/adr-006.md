# ADR-006: Export Content, Formats, and Offline Availability

## Status

Accepted

## Date

2026-08-10

## Context

Users need to export map data for use in QGIS, ArcGIS, and other tools. ReatCarto supports offline field work with IndexedDB storage and sync. Export and import availability must balance field usability with technical constraints of Shapefile generation.

## Decision

**Export content** includes:

- Geometry (normalized to GeoJSON simple features in WGS84).
- Element attributes: name, description, category.
- Style properties: color, stroke width, opacity, and other values stored in the element `style` JSONB, serialized as attribute fields in Shapefile DBF and GeoJSON `properties`.

Photos are **not** included in exported files.

**Format availability:**

| Operation | GeoJSON | Shapefile (.zip) |
|-----------|---------|------------------|
| Export online | Yes | Yes |
| Export offline | Yes (from local store) | No — requires connection |
| Import online | Yes | Yes |
| Import offline | Yes (queued for sync) | Yes (parsed client-side, queued for sync) |

**Export file structure:**

- GeoJSON: a single `FeatureCollection` with one `Feature` per element.
- Shapefile: a `.zip` archive containing `.shp`, `.shx`, `.dbf`, and `.prj` (WGS84).

**Access control:** Only the map owner may import or export GIS data (private and published maps alike). Anonymous visitors and administrators do not receive GIS file download through this feature.

## Alternatives Considered

### Alternative 1: Include photo URLs in export

- **Description**: Export photo paths or signed URLs as attributes.
- **Pros**: Richer dataset for external tools.
- **Cons**: Shapefile 254-char limit; URLs expire; privacy concerns on shared files.
- **Why rejected**: User chose attributes + styles only.

### Alternative 2: Shapefile export offline

- **Description**: Generate Shapefile zip entirely client-side offline.
- **Pros**: Full offline parity.
- **Cons**: Heavy on mobile devices; large dependency footprint.
- **Why rejected**: User chose GeoJSON offline, Shapefile online only.

### Alternative 3: Public map GIS export for anonymous users

- **Description**: Allow anyone to download GeoJSON/Shapefile of published maps.
- **Pros**: Open data sharing.
- **Cons**: Conflicts with owner-only access decision; separate from cartographic PDF export scope.
- **Why rejected**: User chose owner-only access.

## Consequences

### Positive

- GeoJSON export works in disconnected field conditions.
- Exported files are immediately usable in standard GIS desktop tools.
- Style information preserves visual identity across tools that read attributes.

### Negative

- Shapefile export unavailable offline.
- Shapefile field names truncated to 10 characters on export.
- No photo interchange through GIS files.

### Risks

- Client-side Shapefile writing may mishandle edge-case geometries; mitigated by using validated stored geometries and established libraries.

## Implementation Notes

- File naming: include map name and date (e.g., `mapa-exemplo-2026-08-10.geojson`).
- GeoJSON coordinate precision: six decimal places (~11 cm) is acceptable for export.

## References

- Existing cartographic export (`exportar-mapa` task) — separate concern (PDF/PNG)
- Market: Shapefile DBF 10-char field name limit is industry-standard constraint
