# ADR-002: Import Strategy — User-Chosen Merge or Replace

## Status

Accepted

## Date

2026-08-10

## Context

Importing external data into a map that already contains field-collected elements risks either duplicating geometry (unwanted merge) or silently destroying existing work (unwanted replace). Field users operate in connected and disconnected environments and need explicit control.

## Decision

Each import presents a strategy choice:

- **Add (merge)**: New elements are created alongside existing ones. Element count after import must not exceed the per-map limit (5,000).
- **Replace**: All existing elements in the map are removed and replaced by imported features. The user must confirm this destructive action with an explicit warning before proceeding.

Import always concludes with a review step (attribute mapping per ADR-003, validation summary per ADR-005) before any data is written.

## Alternatives Considered

### Alternative 1: Always merge

- **Description**: Imported features are always appended.
- **Pros**: No data loss risk.
- **Cons**: Cannot use import to refresh a map from an external source of truth.
- **Why rejected**: User needs replace option for full refresh workflows.

### Alternative 2: Always replace

- **Description**: Import overwrites all existing elements.
- **Pros**: Clean state after import.
- **Cons**: High risk of accidental data loss in field workflows.
- **Why rejected**: User needs merge option for additive workflows.

### Alternative 3: System decides by file metadata

- **Description**: Infer merge vs replace from file properties or naming.
- **Pros**: Fewer user decisions.
- **Cons**: Unpredictable behavior; no standard signal in GeoJSON/Shapefile.
- **Why rejected**: Unreliable and opaque to users.

## Consequences

### Positive

- Users control additive vs refresh workflows explicitly.
- Replace requires deliberate confirmation, reducing accidental loss.

### Negative

- Extra decision step on every import.
- Replace mode is irreversible without undo (if undo is not extended to bulk import).

### Risks

- Replace during offline work may delete locally unsynced elements; mitigated by warning text mentioning unsynced changes when applicable.

## Implementation Notes

- Replace deletes all elements in the target map, not photos (photos remain attached to deleted elements per existing deletion semantics — confirm in TechSpec whether photos of replaced elements are orphaned or deleted).
- Merge must validate remaining capacity: `current_count + valid_import_count <= 5000`.
