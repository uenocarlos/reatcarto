# ADR-012: Mixed-Geometry Shapefile Export — Separate Files per Type

## Status

Accepted

## Date

2026-08-10

## Context

Shapefile format does not support mixed geometry types in a single layer. Maps may contain points, lines, and polygons together. US-003.EC-3 deferred packaging to TechSpec.

## Decision

When an export scope contains more than one geometry type, the server produces **separate shapefile sets inside one zip archive**, one per type present:

| Geometry type | File basename |
|---------------|---------------|
| Point | `{map-slug}-points` |
| LineString | `{map-slug}-lines` |
| Polygon | `{map-slug}-polygons` |

Each set includes `.shp`, `.shx`, `.dbf`, `.prj` (EPSG:4326). The export dialog lists which layers will be included before download.

## Alternatives Considered

### Alternative 1: Block mixed-type Shapefile export

- **Description**: Require homogeneous geometry in export scope.
- **Pros**: Simplest packaging.
- **Cons**: Forces users to export multiple times or filter manually.
- **Why rejected**: User chose separate files per type.

### Alternative 2: Single shapefile with one dominant type

- **Description**: Export only the most common geometry type.
- **Pros**: One file.
- **Cons**: Silent data loss.
- **Why rejected**: Unacceptable data loss.

## Consequences

### Positive

- Compatible with QGIS, ArcGIS, and other desktop tools.
- No geometry type is dropped.

### Negative

- Users receive multiple layers instead of one.
- Zip may contain only one shapefile set when scope is homogeneous.

### Risks

- Users expecting a single `.shp`; mitigated by pre-download layer list in the export dialog.

## Implementation Notes

- GeoJSON export is unaffected: single `FeatureCollection` with mixed types is valid.
- Empty geometry types are omitted from the zip.
