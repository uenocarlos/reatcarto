# ADR-010: Export Selection via Modal Element Picker

## Status

Accepted

## Date

2026-08-10

## Context

ADR-001 requires whole-map and selected-element export scopes. The map editor currently supports single-element editing (`editingElement`) and visibility toggling (`hiddenIds` for cartographic export), but no multi-select interaction model for GIS data export.

## Decision

When the user chooses scope "selection" in the GIS export dialog, present an element picker inside the modal: a scrollable checklist of all map elements (name, type icon, category) with select-all / clear-all controls. Selected element ids are passed to the export pipeline at confirm time. No changes to the map canvas interaction model.

## Alternatives Considered

### Alternative 1: New multi-select mode on the map canvas

- **Description**: Shift-click or checkbox layer panel for selection.
- **Pros**: Visual selection on map.
- **Cons**: Requires refactoring editor interaction; overlaps with editing workflow.
- **Why rejected**: User chose dialog picker.

### Alternative 2: Reuse `hiddenIds` inversion (visible = selected)

- **Description**: Elements not hidden are exported.
- **Pros**: Reuses existing state.
- **Cons**: Couples GIS export to cartographic visibility; confusing semantics.
- **Why rejected**: User chose dialog picker.

## Consequences

### Positive

- Isolated UX; no editor interaction changes.
- Selection count visible before confirm; empty selection blocked per ADR-001.

### Negative

- Less intuitive than map-click selection for spatial subsets.
- Large maps (5,000 elements) need virtualized list in the picker.

### Risks

- Performance of rendering 5,000 checkboxes; mitigated by virtualized scroll (`@tanstack/react-virtual` or Radix ScrollArea with windowing).

## Implementation Notes

- Picker reads from the same paginated element source as export (see element pagination fix in TechSpec).
- Selection state is ephemeral (dialog-local), not persisted in editor state.
