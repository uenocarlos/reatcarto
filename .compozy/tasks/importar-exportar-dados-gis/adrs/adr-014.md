# ADR-014: Multi-Geometry Normalization Algorithms

## Status

Accepted

## Date

2026-08-10

## Context

ADR-004 specifies that Multi* geometries collapse to single simple types but left the exact algorithms to TechSpec. ReatCarto stores only Point, LineString, and Polygon in EPSG:4326.

## Decision

Apply the following normalization rules client-side before validation summary; server re-validates on batch import:

| Source type | Target | Algorithm |
|-------------|--------|-----------|
| `MultiPoint` | `Point` | First coordinate (ADR-004) |
| `MultiLineString` | `LineString` | Part with greatest length (`@turf/length`); ties → first |
| `MultiPolygon` | `Polygon` | `@turf/union` of all polygon parts; if union fails → invalid |
| `GeometryCollection` | First convertible | Extract first part that normalizes to Point/LineString/Polygon; remainder skipped |
| Unsupported / failed union | — | Marked invalid in validation summary |

After normalization, reproject to EPSG:4326 via `proj4`. Run vertex count and structural checks client-side; `ST_IsValid` runs server-side only.

## Alternatives Considered

### Alternative 1: First-part-only for all Multi* types

- **Description**: Always take the first geometry part.
- **Pros**: Deterministic, fast.
- **Cons**: Loses the most significant geometry in common files.
- **Why rejected**: User chose longest-line and polygon-union.

### Alternative 2: Convex hull for MultiPolygon

- **Description**: Replace with convex hull.
- **Pros**: Always produces a polygon.
- **Cons**: Distorts boundaries significantly.
- **Why rejected**: Union preserves area better.

## Consequences

### Positive

- MultiLineString imports retain the primary route/trace.
- MultiPolygon imports preserve total area when parts are adjacent.

### Negative

- Disjoint MultiPolygon islands may merge into one polygon if union succeeds; user warned in summary.
- Union may fail on invalid topology → feature marked invalid.

### Risks

- Union changes topology; mitigated by preview map and "detail may be lost" notice for Multi* sources.

## Implementation Notes

- Vertex limit (`MAX_VERTICES = 10000`) checked after normalization.
- Coordinates outside valid WGS84 range after reprojection → invalid.
