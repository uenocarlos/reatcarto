# ADR-013: Multi-Layer Shapefile Import — User Picks One Layer

## Status

Accepted

## Date

2026-08-10

## Context

Shapefile zip archives often contain multiple `.shp` layers (e.g., roads, parcels, boundaries). US-008.AC-2 deferred whether to import all layers or let the user choose.

## Decision

When a zip contains multiple shapefile layers, the import dialog shows a **layer selection step** listing each detected layer (basename, feature count estimate, geometry type). The user picks exactly one layer before proceeding to strategy selection and attribute mapping. Single-layer zips skip this step.

## Alternatives Considered

### Alternative 1: Import all layers sequentially

- **Description**: Combine all layers into one import batch.
- **Pros**: Fewer clicks for multi-layer files.
- **Cons**: Conflicting attribute schemas; ambiguous mapping; may exceed element limit unexpectedly.
- **Why rejected**: User chose one-layer selection.

### Alternative 2: Multi-select layers

- **Description**: User checks multiple layers to import together.
- **Pros**: Flexible.
- **Cons**: Same schema conflict issues; complex mapping review.
- **Why rejected**: User chose single-layer selection.

## Consequences

### Positive

- One consistent attribute schema per import.
- Mapping review remains straightforward.

### Negative

- Users with multi-layer files must import each layer separately.

### Risks

- Users may not realize other layers exist; mitigated by showing full layer list with feature counts.

## Implementation Notes

- Layer detection: scan zip for `.shp` files; group with matching `.dbf`/`.shx`.
- After layer pick, parse only the selected layer's component files.
