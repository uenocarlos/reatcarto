# ADR-011: Client-Side GIS File Parsing Libraries

## Status

Accepted

## Date

2026-08-10

## Context

GeoJSON and Shapefile import must work offline (ADR-006). The codebase has no existing shapefile, CRS, or turf dependencies. Parsing, CRS detection, reprojection, and geometry normalization (ADR-004) must run in the browser before the validation summary and batch write.

## Decision

Add the following client-side dependencies:

| Library | Purpose |
|---------|---------|
| `shpjs` | Parse Shapefile binaries from zip |
| `jszip` | Extract `.zip` archives client-side |
| `proj4` | CRS detection and reprojection to EPSG:4326 |
| `@turf/length` | Select longest part of MultiLineString |
| `@turf/union` | Union MultiPolygon parts into single Polygon |

GeoJSON parsing uses native `JSON.parse` with structural validation. No server round-trip for file parsing.

## Alternatives Considered

### Alternative 1: Server-side parsing upload endpoint

- **Description**: Upload raw file; server parses and returns features.
- **Pros**: Offloads CPU from mobile.
- **Cons**: Breaks offline import; requires large upload endpoint.
- **Why rejected**: Offline import is a PRD requirement.

### Alternative 2: `@loaders.gl/shapefile`

- **Description**: loaders.gl shapefile loader.
- **Pros**: Modern API.
- **Cons**: Heavier dependency tree; less community usage for DBF encoding edge cases.
- **Why rejected**: `shpjs` is lighter and sufficient for zip + DBF parsing.

## Consequences

### Positive

- Full offline parse and preview before commit.
- Normalization algorithms run consistently before server validation.

### Negative

- ~200 KB added to client bundle (gzipped estimate).
- Client must mirror server validation rules to avoid surprise rejections on sync.

### Risks

- Client/server validation drift; mitigated by shared constants (`MAX_VERTICES`, `MAX_TEXT_LENGTH`) and server re-validation on batch import.

## Implementation Notes

- DBF decoding: try UTF-8 first, fallback Latin-1 (ISO-8859-1).
- Max upload size: 50 MB (checked before parsing).
- All parsing logic lives in `src/lib/gis/`.
