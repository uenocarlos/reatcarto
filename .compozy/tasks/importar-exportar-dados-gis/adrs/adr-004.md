# ADR-004: Geometry Normalization and CRS Reprojection

## Status

Accepted

## Date

2026-08-10

## Context

ReatCarto stores all geometries in EPSG:4326 (WGS84) as Point, LineString, or Polygon. External files may use MultiPoint, MultiLineString, MultiPolygon, GeometryCollection, different coordinate reference systems, or invalid geometries. PostGIS validation (`ST_IsValid`) already exists server-side.

## Decision

**Geometry normalization on import:**

- `MultiPoint` → single `Point` using the first point (centroid alternative rejected to keep deterministic behavior).
- `MultiLineString` → single `LineString` by merging connected parts or using the longest part (TechSpec chooses algorithm; user sees one line element).
- `MultiPolygon` → single `Polygon` by union or outer-ring extraction (TechSpec chooses; user sees one polygon element).
- `GeometryCollection` → extract the first convertible geometry; remaining parts reported as skipped in the validation summary.
- Geometries that cannot be normalized to a supported type are marked invalid in the preview.

**CRS handling:**

- All imported coordinates are reprojected to EPSG:4326 before storage.
- When a `.prj` file or GeoJSON CRS hint is present, use it as the source CRS.
- When CRS is unknown, assume EPSG:4326 and show a warning that coordinates were treated as WGS84.
- The user always sees a CRS notice in the import preview (detected CRS, assumed CRS, or reprojection applied).

## Alternatives Considered

### Alternative 1: Reject non-WGS84 and unsupported types

- **Description**: Strict acceptance of Point/LineString/Polygon in EPSG:4326 only.
- **Pros**: Simplest validation.
- **Cons**: Rejects most real-world Shapefiles (SIRGAS 2000, UTM zones).
- **Why rejected**: User chose automatic reprojection.

### Alternative 2: Split Multi* into multiple elements

- **Description**: Each part of a MultiPolygon becomes a separate map element.
- **Pros**: Preserves all parts without geometry merging.
- **Cons**: Inflates element count; may hit 5,000 limit; changes semantic identity of features.
- **Why rejected**: User chose single-element conversion.

### Alternative 3: Prompt user for source CRS

- **Description**: Ask user to pick CRS when ambiguous.
- **Pros**: Maximum accuracy for edge cases.
- **Cons**: Requires GIS knowledge; friction in field use.
- **Why rejected**: User chose automatic reprojection with warning.

## Consequences

### Positive

- Accepts common Brazilian and international Shapefiles without manual preprocessing.
- Keeps element model simple (one element = one simple geometry).

### Negative

- Complex Multi* geometries may lose detail when collapsed to a single element.
- Automatic CRS detection from `.prj` can fail on malformed projection files.

### Risks

- Incorrect CRS assumption places features in wrong location; mitigated by preview map showing imported features before commit and CRS warning text.

## Implementation Notes

- Existing vertex limit: 10,000 vertices per line/polygon element (`MAX_VERTICES`).
- Existing validity check: `ST_IsValid` after reprojection.
- Export always writes EPSG:4326 with a `.prj` file for Shapefile.
